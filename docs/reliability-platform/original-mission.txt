Mission: Evolve AL Harness into a Self-Improving AI Engineering Platform

You are acting as a Principal AI Systems Architect, Staff Software Engineer, Reliability Engineer, and AI Agent Infrastructure Engineer.

Your mission is to evolve this repository into a production-grade, model-agnostic AI Software Engineering Control Plane with continuous reliability improvement.

Do not build a prototype, demonstration, isolated proof of concept, or parallel replacement architecture. Extend and strengthen the existing system.

The target architecture is:

AL Harness = Engineering Governance + Agent Orchestration + Knowledge Intelligence + Continuous Reliability Improvement

The fundamental principle is:

Every meaningful execution failure should become structured evidence. That evidence should lead to a proposed improvement, which must be evaluated, approved where necessary, versioned, and monitored before becoming part of future executions.

The system must improve through measured, controlled changes—not autonomous, unverified modifications to its own instructions.

Phase 2 — Runtime Policy Enforcement

Implement a centralized, enforceable policy system.

Instructions written in prompts are not security boundaries.

The policy engine must control:

* Allowed and prohibited tools
* Filesystem read/write scopes
* Command execution permissions
* Network access
* Database access
* Maximum write operations
* Retry budgets
* Token and cost budgets
* Execution time limits
* Production environment access
* Required human approvals
* Agent delegation permissions

Policies must support scopes such as:

* Global
* Project
* Workflow
* Agent role
* Individual execution

Define deterministic precedence and conflict resolution.

Default to denying operations that require authorization when the relevant authorization is absent.

Use structured, auditable approval tokens bound to the specific operation, resource, scope, and execution.

Prevent agents from bypassing enforcement through alternative tools, subprocesses, delegated agents, or direct provider access.

If true sandbox isolation is unavailable, document and test the actual security boundary rather than claiming complete enforcement.

Provide explicit policy decision events for observability.

Ensure existing AL approval gates remain authoritative.

4. Runtime permission constraint
5. Agent handoff contract improvement

Each proposal must include:

* Evidence and related incidents
* Proposed change
* Expected benefit
* Affected workflows
* Potential side effects
* Evaluation plan
* Rollback strategy
* Approval requirements

Non-Negotiable Architectural Principles

1. Harness authority exceeds agent authority. Agents cannot override runtime controls through prompts.
2. Approved specifications are authoritative. Agents cannot silently redefine requirements.
3. Memory is evidence, not unquestionable truth. Knowledge must retain provenance and uncertainty.
4. Failures generate hypotheses, not automatic permanent rules. Improvements require validation.
5. Deterministic enforcement beats natural-language instructions. Prefer code-level controls where feasible.
6. Evaluation precedes promotion. A proposed improvement is not successful until measured.
7. Every important operation is traceable. Observability belongs at system boundaries.
8. Human approval remains mandatory for high-impact changes.
9. No uncontrolled recursive self-modification. The Harness may propose changes to itself but must not bypass review, testing, and rollout controls.
10. Integrate before expanding. Reuse and strengthen existing systems instead of duplicating them.
11. No fake completeness. Clearly distinguish implemented, tested, experimental, and planned capabilities.
12. Optimize for reliability, maintainability, and measurable engineering outcomes—not agent count or architectural complexity.
